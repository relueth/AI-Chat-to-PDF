# AI Chat to PDF 拡張機能 仕様書

- **文書バージョン**: 1.0
- **対象バージョン**: 1.0.0
- **更新日**: 2026-09-11
- **対象ブラウザ**: Google Chrome（Manifest V3 対応版）
- **実装場所**: `extension/`

## 1. 概要

AIチャットサービスの会話をページ上のDOMから抽出し、数式・コード・表・画像を可能な限り保持したまま、PDF、HTML、またはテキストとして保存するChrome拡張機能である。抽出処理は対象サービスごとのDOM設定と汎用フォールバックを組み合わせ、仮想スクロールにより画面外にある会話も収集する。

本拡張機能は会話データを外部サーバーへ送信しない。抽出データは拡張機能のセッションストレージに一時保存し、エクスポートページで利用後に削除する。

## 2. 対応範囲

### 2.1 対応サービス

| 識別子 | サービス | 対応URLの例 | 備考 |
|---|---|---|---|
| `kimi` | Kimi | `kimi.ai`, `kimi.com`, `kimi.moonshot.cn` | Kimi系サブドメインを含む |
| `gemini-notebook` | Gemini Notebook / NotebookLM | `notebook.google.com`, `notebooklm.google.com`, `notebook.cloud.google.com`, Geminiの`/notebook`系パス | Geminiより先に判定 |
| `gemini` | Gemini | `gemini.google.com` | Notebookパスを除く |
| `claude` | Claude | `claude.ai` | |
| `genspark` | Genspark | `genspark.ai`, `www.genspark.ai` | チャット、Copilot、Agent等のDOM変動に対応 |
| `chatgpt` | ChatGPT | `chatgpt.com`, `chat.openai.com` | `data-message-author-role`を優先 |
| `grok` | Grok | `grok.com`, `x.com/i/grok`, `x.com/grok`等 | X/Twitter上のGrokパスを含む |

対象URL以外では、ポップアップの実行ボタンを無効化し、非対応ページであることを表示する。

### 2.2 出力形式

| 形式 | 拡張子 | 動作 | 数式 |
|---|---|---|---|
| PDF | ユーザーが保存 | エクスポートページを開き、ブラウザ標準の印刷ダイアログを表示 | KaTeX描画済みHTMLとローカルKaTeXフォントを使用 |
| HTML | `.html` | CSSを取り込んだHTMLを自動ダウンロード | KaTeX CSSへのCDN参照を含む |
| テキスト | `.txt` | BOM付きUTF-8のMarkdown風テキストを自動ダウンロード | KaTeXのTeX注釈を`$...$`または`$$...$$`へ復元 |

エクスポートページ上では、初回選択形式にかかわらずPDF・HTML・テキストを再出力できる。

## 3. 利用フロー

1. 対応サービスの会話ページをChromeで開く。
2. ツールバーから本拡張機能を開く。
3. 対象サービスが自動判定される。
4. PDF、HTML、テキストのいずれかを選択する。
5. 実行ボタンを押す。
6. Content Scriptが会話DOMを走査し、スクロールしながら全メッセージを収集する。
7. 画像を可能な範囲でBase64 Data URLへ変換し、抽出HTMLをサニタイズする。
8. `{site, siteName, title, url, exportedAt, messages}`形式のデータを`chrome.storage.session`へ保存する。
9. 新しいエクスポートタブを開く。
10. エクスポートページがデータを描画し、選択形式の処理を自動実行する。
11. 抽出データをセッションストレージから削除する。

## 4. 機能仕様

### 4.1 ポップアップ

- 現在のアクティブタブのURLから対応サービスを判定する。
- サービス名をバッジ表示する。
- 非対応ページでは説明文を表示し、実行ボタンを無効化する。
- 形式変更時に、選択形式の説明と実行ボタンのラベルを更新する。
- 抽出中は進捗件数を表示する。
- Content Script未注入時は`chrome.scripting.executeScript`で再注入して再試行する。
- 抽出の初回タイムアウトは45秒、再試行時は120秒とする。
- 抽出件数を表示し、成功時にエクスポートタブを開く。

### 4.2 会話抽出

- サービスごとのメッセージコンテナ、ユーザー、AI応答、本文、タイトル用セレクタを使用する。
- セレクタ候補は複数定義し、対象サービスのDOM変更に対する耐性を持たせる。
- 親子要素が重複して検出された場合は最上位候補に絞る。
- メッセージのroleは`user`または`assistant`とする。
- ユーザーとAIの両方を含むターンコンテナは、DOM順に分割する。
- role判定が不十分な場合は、AI本文とその直前のユーザー候補を組み合わせる汎用フォールバックを実行する。
- ユーザー発言が取得できない場合は、ページ上のプロンプト候補から初回クエリを補完する。
- 同一メッセージはハッシュキーで重複排除する。
- 収集順序は会話の先頭から末尾になるように整列する。
- 安全上限として最大800メッセージまで返す。

### 4.3 仮想スクロール対応

1. 会話要素からスクロールコンテナを推定する。
2. コンテナを一度末尾まで移動する。
3. 表示領域を約90%ずつ上方向へ移動する。
4. 各位置で表示中のメッセージを収集し、ハッシュキーで統合する。
5. 最上部到達、または最大300ステップで終了する。
6. 先頭まで到達できない場合でも、取得済みメッセージを返す。

### 4.4 HTMLの正規化・サニタイズ

抽出時とエクスポート時の二段階で、次の処理を行う。

- `script`、`iframe`、`object`、`embed`、フォーム、不要な`style`等を除去する。
- `on*`イベント属性を除去する。
- `href`および`src`の`javascript:` URLを除去する。
- コピー、評価、アクションバー、入力欄、不要なヘッダー等を除去する。
- アバター、トラッキングピクセル、小型アイコン等を原則除外する。
- リンクは新規タブで開く設定と`noopener`を付与する。
- KaTeX、MathJax等の数式コンテナ内部は、数式レイアウト維持のため必要な属性・SVG・インラインスタイルを保持する。
- Notebook系の引用ボタンは`[番号]`形式の`sup`バッジへ変換する。

### 4.5 画像処理

対象画像は、`img`、`canvas`、SVGの`image`、CSSの`background-image`、添付ファイル用カスタム属性から探索する。

- ユーザー添付画像、AI生成画像、会話本文内画像を対象とする。
- 画像URLは絶対URLへ正規化する。
- Canvas変換時は白背景を敷き、最大幅・高さ1200px、JPEG品質0.82を基本とする。
- Content Script内の変換に失敗した場合は、fetch、Imageオブジェクト、Background Service Workerの順にフォールバックする。
- Background Service Workerでは`host_permissions`を利用して画像を取得し、Base64 Data URL化する。
- 変換結果は抽出処理中のメモリキャッシュで再利用する。
- `blob:` URLを変換できない場合は、エクスポート先で無効になるため無理に保持しない。

### 4.6 エクスポートページ

- セッションストレージから抽出データを読み込む。
- サービス名、会話タイトル、メッセージ件数、エクスポート日時、元URLを表示する。
- ユーザー発言は「あなた」、AI発言はサービス名でラベル表示する。
- 本文は白背景の読みやすいレイアウトで表示する。
- KaTeXの自動レンダリング対象は`$...$`、`$$...$$`、`\(...\)`、`\[...\]`および一部のLaTeX環境とする。
- 未変換の数式ブロックにはKaTeXの明示レンダリングを試行する。
- PDF印刷時はツールバーとローディング表示を非表示にする。
- メッセージ、数式、コードブロック、表、引用、画像の途中での改ページを避ける。
- 印刷ページ余白は上下18mm、左右14mmを基本とする。

## 5. データ仕様

### 5.1 セッションストレージキー

| キー | 型 | 保存期間 |
|---|---|---|
| `ai2pdf_payload` | `ExportPayload` | エクスポートページの初期化後に削除。タブ・セッション終了時にも消滅 |

### 5.2 ExportPayload

```json
{
  "site": "chatgpt",
  "siteName": "ChatGPT",
  "title": "会話タイトル",
  "url": "https://chatgpt.com/...",
  "exportedAt": "2026-09-11T00:00:00.000Z",
  "messages": [
    {
      "key": "kabc123",
      "role": "user",
      "html": "<p>質問本文</p>"
    },
    {
      "key": "kdef456",
      "role": "assistant",
      "html": "<p>回答本文</p>"
    }
  ]
}
```

`messages[].html`はサニタイズ済みの本文HTMLであり、`role`は`user`または`assistant`に限定する。`key`は同一会話内の重複排除に利用する。

## 6. 権限・構成仕様

### 6.1 Chrome権限

| 権限 | 用途 |
|---|---|
| `storage` | 抽出結果を`chrome.storage.session`へ一時保存 |
| `activeTab` | アクティブタブの会話抽出 |
| `tabs` | アクティブタブの取得、エクスポートタブの作成 |
| `scripting` | Content Scriptの手動再注入 |
| `host_permissions: <all_urls>` | CORS制限のある画像をBackground Service Workerから取得 |

### 6.2 コンポーネント

- `manifest.json`: Manifest V3定義、URLマッチ、権限、エントリポイント。
- `popup/`: サービス判定、形式選択、抽出開始、進捗・エラー表示。
- `content/content.js`: サービス判定、DOM抽出、仮想スクロール収集、画像埋め込み、サニタイズ。
- `background/background.js`: 画像取得、リサイズ、Base64化。
- `export/`: 抽出データの表示、PDF印刷、HTML・テキスト出力。
- `lib/katex/`: KaTeX本体、auto-render、CSS、フォント。
- `_locales/ja/`: 日本語の拡張機能名・説明。

## 7. エラー仕様

| コード | 発生条件 | ユーザーへの表示 |
|---|---|---|
| `UNSUPPORTED_SITE` | URLまたはDOMが対応サービスに一致しない | このページは対応していません |
| `NO_MESSAGES` | 会話メッセージを1件も抽出できない | 会話を開いた状態でもう一度試すよう案内 |
| `EXTRACT_FAILED` | 抽出中に予期しない例外が発生 | ページ再読み込みを案内 |
| `TIMEOUT` | 抽出処理が制限時間を超過 | 抽出がタイムアウトしたと表示 |
| ストレージ保存失敗 | セッションストレージ保存時の例外 | エラー表示。保存処理を再試行 |
| 画像取得失敗 | CORS、認証期限、ネットワーク等 | 本文を優先し、画像は取得できた範囲で出力 |

## 8. セキュリティ・プライバシー要件

- 会話データを外部API、拡張機能提供者のサーバーへ送信しない。
- 会話データは`chrome.storage.session`にのみ保存し、永続ストレージへ保存しない。
- エクスポートHTMLにスクリプト、iframe、イベントハンドラ、`javascript:` URLを持ち込まない。
- 外部画像は可能な限りData URLへ変換し、出力後の認証切れ・セッション切れによるリンク切れを抑止する。
- リンクを新規タブで開く場合は`rel="noopener"`を設定する。
- `host_permissions`による画像取得は、会話内画像の埋め込み目的に限定する。
- 元URLはエクスポート文書のメタ情報として出力されるため、共有時の情報漏えいに注意する。

## 9. 非機能要件

- **互換性**: Manifest V3をサポートするChromeで動作すること。
- **可読性**: 出力は白背景を基本とし、ユーザーとAIの発言を視覚的に区別できること。
- **数式品質**: 既に描画済みのKaTeX/MathJaxを優先して保持し、未変換TeXは可能な範囲で再描画すること。
- **耐障害性**: セレクタ複数候補、roleフォールバック、画像取得フォールバックを備えること。
- **性能**: 同一画像をキャッシュし、大量会話は最大800メッセージで制限すること。
- **データ消去**: エクスポートページの初期化後に一時データを削除すること。
- **オフライン性**: PDF出力は拡張機能内蔵のKaTeX資産で動作すること。HTML出力のKaTeX CSSはCDN参照を含むため、完全なオフライン閲覧は保証しない。

## 10. 受け入れ基準

### 10.1 基本動作

- 対応7サービスの対象URLで拡張機能を開くとサービス名が表示される。
- 非対応URLでは実行できない。
- 各形式を選択して会話抽出を開始できる。
- 抽出成功後に新しいエクスポートタブが開く。

### 10.2 抽出品質

- ユーザー発言とAI発言がDOM順に出力される。
- 長い会話で画面外のメッセージも可能な範囲で含まれる。
- 同一メッセージが重複しない。
- タイトル、サービス名、元URL、エクスポート日時が表示される。
- コピーボタン、評価ボタン、操作バーなどが本文に混入しない。

### 10.3 出力品質

- PDF印刷時にツールバーが印刷されない。
- 数式、コード、表、引用、画像が崩れず表示される。
- HTMLファイルをブラウザで開いて本文を閲覧できる。
- テキストファイルがUTF-8で読み込め、日本語が文字化けしない。
- テキスト内で見出し、リスト、表、コード、リンク、数式が判別できる。

### 10.4 安全性

- 抽出本文に含まれる`script`、`iframe`、イベント属性が出力HTMLに残らない。
- `javascript:` URLが出力HTMLに残らない。
- エクスポート完了後、`ai2pdf_payload`がセッションストレージから削除される。

## 11. 制約・既知の問題

- 対応サービス側のDOM変更により、セレクタの更新が必要になる場合がある。
- 認証が必要な画像、アクセス制限された画像、変換できない`blob:`画像は欠落する可能性がある。
- PDFはChromeの印刷機能に依存するため、最終的なページ分割や印刷設定はChromeの環境に左右される。
- HTML出力はKaTeX CSSをCDNから参照するため、閲覧時にネットワークが必要になる場合がある。
- 会話は最大800メッセージまでで、それを超える分は出力しない。
- ダークテーマ出力、最新N件などの抽出範囲指定、`.md`直接出力は現行仕様の対象外とする。

## 12. 保守方針

- 対象サービスのDOM変更時は、まず`content/content.js`の該当`SITE_CONFIGS`を更新する。
- ChatGPTは`data-message-author-role`を優先してrole判定する。
- Gensparkは通常セレクタで抽出できない場合に汎用フォールバックが動作するため、フォールバック誤検出も併せて確認する。
- 変更後は、各出力形式、数式、画像、仮想スクロール、サニタイズ、エラー表示を回帰確認する。
- 対応サイトを追加する場合は、URLマッチ、ポップアップ判定、`SITE_CONFIGS`、タイトル抽出、抽出テストを同時に更新する。
